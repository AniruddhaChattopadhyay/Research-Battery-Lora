## Schema normalization (`src/normalize.py`)

- v0 (no direction in the prompt): 1,300 → 951 canonical names. Error: `directed_by` → `directed`
  without the inverse flag.
- v1 (each canonical relation has a "subject type -> object type" direction): 1,300 → 1,069 canonical
  names, 32 inverse. `starred_in` → `starring` (inverse) and `has_member` → `member_of` (inverse) are
  correct. `born_in_year` → `born_on` is correct. But `directed` and `directed_by` stay two relations,
  and `wrote` and `written_by` also stay two relations. Cost $0.02.
- Next: a second pass that merges canonical relations with each other. Embedding similarity finds the
  candidate pairs, and the LLM decides (the EDC method). Do not merge on embedding similarity alone:
  at cosine 0.85, `born_in` (a place) matched `born_on` (a time).

## C2: do open slots predict later facts? (`analysis/anticipation.py`)

HotpotQA slice, 2,341 open slots that have a later batch:

| Measure | Raw relations | Normalized (v1) |
|---|---|---|
| A later batch binds the slot (same relation) | 2.1% | 3.0% |
| Same, with a random relation instead (20 draws) | 0.9% | 1.1% |
| A later batch gives any fact about the entity (ceiling) | 10.7% | 11.5% |
| The fact was already in memory (earlier or same batch) | 1.9% | 2.5% |

Reading:
1. The predicted relation is 2.7× better than a random relation. When a later passage talks about
   the entity, it gives the predicted relation 26% of the time (random: 10%).
2. The ceiling is low. Pooled HotpotQA passages seldom come back to the same entity. So HotpotQA is a
   weak test of C2. C2 needs a stream where entities come back over time: FinanceBench (one company,
   many years), dated news (StreamingQA, MultiHop-RAG), or LongMemEval sessions.
3. 2.5% of the slots were already answered by memory. The agent must check memory before it opens a slot.
4. The most common open relations are born_in (645), born_on (325) and founded_in_year (246).

C2 (raw relation names): later batches bind 1.2% of the open slots, against 0.44% for a random
relation (2.8×). The ceiling (any later fact about the entity) is 10.4%. Memory already had the fact
for 1.9% of the slots.

Reading:
1. MuSiQue has room. The oracle is 15 judge points above dense, and closed-book is only 0.39.
2. The inferred-question index helps retrieval: +4.5 Recall@5 over the same graph without it
   (19 questions better, 6 worse). The interval touches zero, so we need the 1,000-question run.
3. QBranch is not better than dense yet (+2 judge points, inside the noise).
4. The largest gap is on 4-hop questions: every system gets about 0.36, and the oracle gets 0.73. The
   v0 retriever does only one hop of expansion. A path plan (figure panel c, step 2) or iterative
   retrieval should help most here. This is the next thing to build.
5. C2 shows the same pattern as HotpotQA: about 3× better than chance, with a low ceiling.
